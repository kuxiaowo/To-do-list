# API Reference

[中文](../zh-CN/API.md) | [English](./API.md)

This document describes the HTTP API provided by `server.py`. All interfaces return JSON. Unless otherwise specified, the request body also uses JSON.

## General convention

Base address:

```text
http://localhost:8092
```

Request header:

```http
Content-Type: application/json
Authorization: Bearer <token>
```

When accessing some read interfaces without logging in, read-only empty data will be returned; writing, updating, and deleting interfaces must be logged in.

Request body constraints:

- The top level of the JSON request body must be an object.
- The maximum size of a single JSON request body is 5 MiB; the base64 content of the avatar upload is also included in this limit.
- Unmatched `/api/...` paths return a JSON 404 instead of an HTML error page.

Generic error response:

```json
{
  "error": "error message"
}
```

Some business errors will return additional fields such as `message`, `usedMinutes`, `capacityMinutes`, etc., and the front end will display `message` first.

## Data model

### User

```json
{
  "id": 1,
  "name": "Zhang San",
  "nickname": "zhangsan",
  "role": "student"
}
```

### Task

```json
{
  "id": "task-1710000000000-abcd1234",
  "userId": 1,
  "title": "Complete physics homework",
  "subject": "Physics",
  "dueAt": "2026-05-18T23:59:00",
  "priority": "medium",
  "note": "No. 3 Chapter Exercises",
  "completed": false,
  "createdAt": "2026-05-18T13:00:00Z",
  "updatedAt": "2026-05-18T13:00:00Z"
}
```

Description:

- `id` Up to 128 characters; if not passed when creating the task, it will be generated by the backend.
- `title` Required, maximum 120 characters.
- `subject` Required, up to 40 characters; value can come from account template or user-defined text.
- `priority` Optional values: `high`, `medium`, `low`.
- When `dueAt` is an empty string, it indicates an unscheduled task; when it is not empty, `YYYY-MM-DDTHH:mm:ss` must be used.
- `note` Maximum 4000 characters.
- `completed` must be a JSON boolean.

### ScheduleItem

```json
{
  "id": "schedule-1710000000000-abcd1234",
  "userId": 1,
  "taskId": "task-1710000000000-abcd1234",
  "date": "2026-05-18",
  "slotKey": "2026-05-18-dynamic",
  "slotLabel": "Daily schedule",
  "slotStart": "00:00",
  "slotEnd": "23:59",
  "startTime": "18:05",
  "endTime": "18:35",
  "durationMinutes": 30,
  "note": "Review wrong questions",
  "completed": false,
  "createdAt": "2026-05-18T13:00:00Z",
  "updatedAt": "2026-05-18T13:00:00Z",
  "task": {
    "id": "task-1710000000000-abcd1234",
    "title": "Complete physics homework",
    "subject": "Physics",
    "dueAt": "2026-05-18T23:59:00",
    "priority": "medium"
  }
}
```

### Slot (compatible with older versions)

```json
{
  "keyBase": "1-18:00",
  "label": "After dinner",
  "start": "18:00",
  "end": "18:40"
}
```

Description:

- The new version of daily schedule no longer relies on the time grid; `slotKey`, `slotLabel`, `slotStart`, `slotEnd` are only returned as old data compatible fields.
- `keyBase` is the time grid stable identifier within the same day.
- `start` and `end` use `HH:mm`.

## Authentication interface

### Register

```http
POST /api/auth/register
```

Request:

```json
{
  "name": "Zhang San",
  "nickname": "zhangsan",
  "password": "123456"
}
```

Response:

```json
{
  "token": "session-token",
  "user": {
    "id": 1,
    "name": "Zhang San",
    "nickname": "zhangsan",
    "role": "student"
  }
}
```

Status code:

- `200 OK`: Registration successful and automatic login.
- `400 Bad Request`: Field is missing, field is too long, or password is less than 6 characters.
- `409 Conflict`: Nickname already exists.

### Login

```http
POST /api/auth/login
```

Request:

```json
{
  "nickname": "zhangsan",
  "password": "123456"
}
```

The response is the same as the registration interface.

Status code:

- `200 OK`: Login successful.
- `401 Unauthorized`: Incorrect nickname or password.

### Get the current user

```http
GET /api/auth/me
```

Response:

```json
{
  "user": {
    "id": 1,
    "name": "Zhang San",
    "nickname": "zhangsan",
    "role": "student"
  }
}
```

Status code:

- `200 OK`: token is valid.
- `401 Unauthorized`: Not logged in or token expired.

### Log out

```http
POST /api/auth/logout
```

Response:

```json
{
  "ok": true
}
```

## ManageBac Helper installation package download

### Get the installation package download

```http
GET /api/managebac-helper/installer
Authorization: Bearer <token>
```

Behavior:

- Login required.
- When configuring OSS, return a short-term pre-signed download URL.
- When OSS is not configured, return the local installation package file stream.
- Each time you successfully generate an OSS URL or send a local installation package, it will be counted in the download statistics.

OSS response:

```json
{
  "ok": true,
  "source": "oss",
  "url": "https://...",
  "expiresSeconds": 600,
  "limit": {
    "windowHours": 24,
    "linkLimit": 5,
    "source": "global",
    "hasOverride": false
  },
  "usage": {
    "linkCount": 1
  }
}
```

Status code:

- `200 OK`: Returns the OSS URL or local file stream.
- `401 Unauthorized`: Not logged in.
- `429 Too Many Requests`: The number of download link generation times reaches the current user limit.

### Create task

```http
POST /api/tasks
```

Request:

```json
{
  "id": "task-1710000000000-abcd1234",
  "title": "Complete physics homework",
  "subject": "Physics",
  "dueAt": "2026-05-18T23:59:00",
```

Response:

Status code:

- `200 OK`: Update successful.
- `400 Bad Request`: The title or subject is missing, a field is too long, `dueAt` has an invalid format, `priority` / `pool` is invalid, or `completed` is not a Boolean value.
- `401 Unauthorized`: Not logged in.

Response:

```json

```

Note: When deleting a single task, the daily schedule corresponding to the task will be deleted simultaneously.

## Daily scheduling interface

### Get daily schedule

```http
GET /api/schedule-items
```

Response:

```json
{
  "items": [],
  "readOnly": false
}
```

Returns when not logged in:

```json
{
  "items": [],
  "readOnly": true
}
```

### Create daily schedule

```http
POST /api/schedule-items
```

Request:

```json
{
  "taskId": "task-1710000000000-abcd1234",
  "date": "2026-05-18",
  "startTime": "18:05",
  "durationMinutes": 30,
  "note": "Review wrong questions",
  "completed": false
}
```

Response:

```json
{
  "ok": true,
  "id": "schedule-1710000000000-abcd1234"
}
```

Status code:

- `201 Created`: Created successfully.
- `400 Bad Request`: The task does not exist, the date or start time is missing, the duration is illegal, or the task is scheduled to span to the next day.
- `401 Unauthorized`: Not logged in.

Daily schedule no longer relies on time period templates. End time is automatically calculated by `startTime + durationMinutes`; schedules for the same date allow overlapping times. When querying the schedule, each instance returns:

```json
{
  "startTime": "18:05",
  "endTime": "18:35",
  "hasConflict": true,
  "conflictIds": ["schedule-overlapping-id"]
}
```

Adjacent but non-overlapping intervals are not marked as conflicting; completed arrangements no longer participate in conflict calculations.

### Update daily schedule

```http
PUT /api/schedule-items/{id}
```

The current implementation only updates the following fields:

```json
{
  "startTime": "18:10",
  "durationMinutes": 20,
  "note": "Change to multiple choice questions",
  "completed": true
}
```

Response:

```json
{
  "ok": true,
  "id": "schedule-1710000000000-abcd1234"
}
```

Status code:

- `200 OK`: Update successful.
- `400 Bad Request`: The start time or duration is illegal, or the schedule spans to the next day.
- `401 Unauthorized`: Not logged in.
- `404 Not Found`: The schedule does not exist or does not belong to the current user.

### Delete daily schedule

```http
DELETE /api/schedule-items/{id}
```

Response:

```json
{
  "ok": true
}
```

## Time grid configuration interface

### Get time grid configuration

```http
GET /api/schedule-config
```

Response:

```json
{
  "defaultWeekSlots": {
    "0": [],
    "1": []
  },
  "templateVersions": [
    {
      "id": 1,
      "effectiveFrom": "2026-05-18",
      "slots": {
        "0": [],
        "1": []
      },
      "createdAt": "2026-05-18T13:00:00Z",
      "updatedAt": "2026-05-18T13:00:00Z"
    }
  ],
  "dayOverrides": {
    "2026-05-18": []
  },
  "readOnly": false
}
```

Description:

- `defaultWeekSlots` is the system’s default weekly template.
- `templateVersions` is the one-week template version saved by the user. Press `effectiveFrom` to take effect.
- `dayOverrides` is a custom time grid for a single day, with a higher priority than the weekly template.

### Save template for one week

```http
PUT /api/schedule-template
```

Request:

```json
{
  "effectiveFrom": "2026-05-18",
  "slots": {
    "0": [
      {
        "keyBase": "0-09:00",
        "label": "morning",
        "start": "09:00",
        "end": "10:00"
      }
    ],
    "1": [],
    "2": [],
    "3": [],
    "4": [],
    "5": [],
    "6": []
  }
}
```

Response:

```json
{
  "ok": true
}
```

Note: The template takes effect from `effectiveFrom` for future dates that are not individually customized. If the modification will destroy the time period of the existing arrangement, the interface returns `409 Conflict`.

### Save single day time grid

Response:


```http
DELETE /api/schedule-day-slots/{date}
```

Response:

```json
{
  "ok": true
}
```

Description: Delete the single-day override for this date and make it use the week template again.

### Reset all time grid configurations

```http

```

Response:

```json
{
  "ok": true

```

Description: Delete the current user's weekly template version and all single-day coverage, and restore the system default template. If restoring the default template will destroy the scheduled time period, the interface returns `409 Conflict`.

## AI assistant interface

The AI assistant only generates instructions to be approved and does not directly write tasks in the `/api/ai/...` interface. The client still calls the common task interface during approval execution, so the back-end verification of the task interface is the final guarantee.

The AI ​​context only contains the unfinished `pool=todo` tasks of the current user, and a maximum of 200 tasks are returned to the model; if the actual number exceeds 200, the `taskSelection.truncated` in the response context will prompt the model to ask the user to narrow the range.

### Non-streaming chat

```http
POST /api/ai/chat
Authorization: Bearer <token>
Content-Type: application/json
```

Request:

```json
{
  "message": "Help me create a math task, low priority, put it to be scheduled first",
  "history": [
    { "role": "user", "content": "Previous round of user messages" },
    { "role": "assistant", "content": "Last round of assistant reply" }
  ],
  "locale": "en",
  "clientNow": "2026-06-20T12:00:00.000Z",
  "timezone": "Asia/Shanghai"
}
```

`locale` accepts `zh-CN` or `en`. When it is `en`, the AI assistant writes user-facing replies in English. The default is `zh-CN`.

Response:

```json
{
  "ok": true,
  "reply": "Reply to the user",
  "actions": [
    {
      "id": "ai-action-1",
      "type": "create_task",
      "summary": "Create a task: Complete the exercise / Mathematics / To be arranged / Low",
      "task": {
        "title": "Complete exercise",
        "subject": "Mathematics",
        "dueAt": "",
        "priority": "low",
        "note": ""
      }
    }
  ],
  "rejectedActions": []
}
```

Status code:

- `200 OK`: AI return has been processed; `actions` still needs client approval before execution.
- `400 Bad Request`: The request body is illegal, `message` is missing or exceeds 2000 characters.
- `401 Unauthorized`: Not logged in.
- `429 Too Many Requests`: Current user AI token limit reached.
- `502 Bad Gateway`: DeepSeek request failed.
- `503 Service Unavailable`: `DEEPSEEK_API_KEY` is not configured.

### Streaming Chat

```http
POST /api/ai/chat-stream
Authorization: Bearer <token>
Content-Type: application/json
```

The request body is the same as `/api/ai/chat`. Respond using Server-Sent Events:

```text
event: delta
data: {"text":"Let me sort it out first..."}

event: done
data: {"reply":"Full reply","actions":[],"rejectedActions":[]}
```

Errors are returned as SSE `error` events:

```text
event: error
data: {"error":"DeepSeek request failed","message":"..."}
```

### AI action format

The server only accepts two types of actions:

- `create_task`: can only contain `title`, `subject`, `dueAt`, `priority`, `note`, and is ultimately created as `pool=todo`.
- `update_task`: Only `title`, `subject`, `dueAt`, `priority`, `note` of existing tasks in the context can be modified.

The server will refuse to delete tasks, mark completed, modify daily schedules, modify habits, write unknown fields, use out-of-context task ids, overlong fields or illegal dates. Rejected actions will appear in `rejectedActions`; the backend will try to get the model to regenerate safe actions with repair hints.

## Subject Template API

Subject templates are per-user presets for the task `subject` field. Tasks still store `subject` as plain text and do not require the value to come from the template.

### Get subject template

```http
GET /api/subject-template
```

Response:
```json
{
  "subjects": [
    { "name": "Chinese", "preset": true, "enabled": true },
    { "name": "Mathematics", "preset": true, "enabled": true },
    { "name": "Computer Science", "preset": true, "enabled": true },
    { "name": "History", "preset": false, "enabled": true }
  ],
  "defaultSubjects": ["Chinese", "Mathematics", "English B", "IELTS", "Physics", "Economics", "Chemistry", "Psychology", "Biology", "Computer Science"],
  "readOnly": false
}
```

Status:
- `200 OK`: success.
- `401 Unauthorized`: login required.

### Update subject template

```http
PUT /api/subject-template
```

Request:
```json
{
  "subjects": [
    { "name": "Chinese", "preset": true, "enabled": false },
    { "name": "History", "preset": false, "enabled": true }
  ]
}
```

Notes:
- Preset subjects are always kept by the server; clients can only enable or disable them.
- Custom subjects can be added or removed by including or omitting them from `subjects`.
- Subject names are trimmed, case-insensitively deduplicated, and limited to 40 characters.

Status:
- `200 OK`: saved.
- `400 Bad Request`: invalid payload.
- `401 Unauthorized`: login required.
